들어갈 위치 고르기

지금 볼 탭 · 학습지

아래 미리보기는 내 페이지를 그대로 실행한 화면이에요. 분홍색 ＋ 여기에 넣기 중 하나를 누르면 그 자리에 OX 투표와 방명록이 들어간 모습이 보여요. 미리보기에 보이는 모습이 GitHub에 올렸을 때의 모습과 같아요.

추가되는 코드가 하는 일① 페이지가 열리면 API 주소로 GET 요청을 보내 저장된 레코드를 불러와요. ② 남기기나 O·X를 누르면 POST 요청으로 데이터베이스에 새 레코드를 저장해요. ③ OX 투표는 불러온 레코드에서 O와 X의 개수를 세어(집계) 게이지로 보여 줘요. ④ 화면이 열려 있는 동안 6초마다 다시 GET 요청을 보내서, 다른 사람이 누른 결과도 실시간으로 게이지에 흘러들어요. 미리보기에서는 예시 투표가 몇 초마다 자동으로 늘어나는 모습만 보이고, 실제 저장은 되지 않아요.
확인 지점미리보기에서 원하는 자리에 OX 투표와 방명록이 보이면 통과.

꼭 지킬 약속

내 페이지 주소를 아는 사람은 누구나 쓰고 읽을 수 있어요.닉네임에 실명을 쓰지 않고, 전화번호·주소·다른 사람을 놀리거나 상처 주는 말은 쓰지 않아요.
지우고 싶은 기록이 생기면구글 시트에서 그 줄 번호를 마우스 오른쪽으로 눌러 행 삭제를 고르면 페이지에서도 사라져요. 불쾌한 글이 올라오면 지우기 전에 선생님께 알려요.
한 번만 참여할 수 있는 이유OX와 방명록은 한 기기에서 한 번씩만 할 수 있어요. 참여하면 그 기기의 브라우저에 기록이 남아 버튼이 잠겨요. 하지만 다른 브라우저나 기기에서는 다시 할 수 있어요. 로그인(인증) 없이는 서버가 사람을 구분할 수 없기 때문이에요. 실제 서비스가 로그인을 쓰는 이유예요.

안 될 때

연결 시험에서 실패가 떠요
  • 주소가 https://script.google.com/으로 시작하고 /exec로 끝나는지 보세요.
  • 3차시 4단계 액세스가 모든 사용자인지 보세요. (앱스 스크립트 → 배포 → 배포 관리 → 연필 ✏)
  • 새 탭에 API 주소를 직접 열어 보세요. 로그인 화면이 나오면 액세스 설정 문제예요.
"○○ 탭이 없어요" / "○○ 칸이 없어요"라고 나와요

시트 아래쪽 탭 이름과 1행의 필드 이름을 확인해요. 방명록 탭은 A1 시간 · B1 닉네임 · C1 내용, OX 탭은 A1 시간 · B1 답이어야 해요. 고친 뒤 다시 연결 시험을 눌러요. "새 백엔드 코드가 아니에요"가 나오면 3차시 3단계 코드를 다시 붙여넣고 배포 → 배포 관리 → 연필 ✏ → 버전: 새 버전 → 배포를 해요.

"HTML 코드가 아니에요"라고 나와요

GitHub 화면 전체를 복사했을 수 있어요. 연필 ✏ 화면에서 코드 칸 안을 한 번 누른 뒤 Ctrl+A → Ctrl+C 해요.

"React 코드예요"라고 나와요 / 내 페이지가 흰 화면이에요

2차시에 올린 코드가 웹페이지가 아니라 React 코드예요. Gemini에게 "React 없이 HTML 파일 하나로 다시 만들어 줘"라고 요청해 새 코드를 받고, 그 코드를 2단계 칸에 붙여넣어요.

＋ 여기에 넣기가 안 보이거나 원하는 자리가 없어요

미리보기를 아래로 내려 보세요. 그래도 없으면 맨 아래에 넣기를 눌러요. 페이지 맨 아래에 들어가도 기능은 똑같이 동작해요.

올렸는데 내 페이지에 방명록(투표)이 안 보여요
  • 1~2분 기다린 뒤 Ctrl+F5를 눌러요.
  • GitHub의 index.html 맨 아래쪽에 방명록·투표라는 글자가 있는지 보세요. 없으면 4단계를 다시 해요.
남기기(투표)를 눌렀는데 "서버와 연결하지 못했어요"가 떠요

1단계 연결 시험을 다시 눌러 보세요. 성공이 뜨면 잠시 뒤 다시 시도하고, 실패가 뜨면 위의 첫 번째 항목을 확인해요.

"저장 중…"이 오래 걸려요

여러 명이 동시에 누르면 백엔드가 한 명씩 차례로 저장해서 시간이 걸려요(반 전체가 한꺼번에 누르면 1분 가까이 걸릴 수 있어요). 창을 닫지 말고 기다리면 자동으로 다시 시도해서 저장돼요. 끝내 "서버와 연결하지 못했어요"가 뜨면 잠시 뒤 다시 눌러요.

한 번 더 남기고(투표하고) 싶어요

한 사람이 한 번씩만 참여하는 규칙이라 같은 브라우저에서는 버튼이 잠겨요. 내 글을 고치고 싶으면 시트에서 그 행을 지우고 다른 기기로 다시 남겨요.

오늘의 용어

요청 · 응답프론트엔드가 백엔드에 보내는 것이 요청, 백엔드가 돌려주는 것이 응답
CRUD데이터베이스의 4가지 기본 동작: 생성(Create), 조회(Read), 수정(Update), 삭제(Delete). 오늘 붙인 기능은 생성(POST)과 조회(GET)를 해요.
집계저장된 레코드를 세거나 합쳐서 의미 있는 값을 만드는 것. 예: O와 X의 개수, 비율
폴링일정 시간마다 서버에 요청을 다시 보내 새 데이터를 확인하는 방법. OX 게이지가 실시간으로 바뀌는 원리예요.
인증사용자가 누구인지 확인하는 것. 로그인이 대표적이에요.
웹 앱프론트엔드 + 백엔드 + 데이터베이스가 연결되어 동작하는 웹 서비스

4차시 정리

오늘 만든 것: 자기소개 페이지(프론트엔드) → 앱스 스크립트(백엔드) → 구글 시트(데이터베이스)가 연결된 웹 앱. 요청(POST·GET)과 응답이 어떤 순서로 오가는지 용어 정리에서 다시 확인해요.
