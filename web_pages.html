정적 웹사이트의 구조

지금 볼 탭 · 학습지

GitHub Pages는 저장소에 있는 파일을 그대로 보내 주는 정적 웹사이트예요. 그래서 HTML 파일 하나가 페이지 한 장이 되고, 파일 이름이 주소의 끝부분이 돼요.

개념뜻
index.html폴더 주소(…/my-page/)로 들어오면 가장 먼저 열리는 첫 페이지. 이름을 바꾸면 첫 화면이 404가 돼요.
하이퍼링크 <a href>누르면 href 속성에 적힌 페이지로 이동해요. 메뉴와 버튼은 모두 링크예요.
상대 경로 about.html지금 페이지가 있는 폴더를 기준으로 찾아가는 주소. 저장소 이름이나 아이디가 바뀌어도 그대로 동작해서, 내 사이트 안 이동에 써요.
절대 경로 https://…처음부터 끝까지 다 적은 주소. 다른 사이트로 갈 때 써요.

파일 이름 규칙 — 서버는 대문자와 소문자를 다른 글자로 봐요. 그래서 이름은 영어 소문자·숫자·하이픈(-)만 써요.

좋아요about.html my-menu.html gallery2.html
안 돼요소개.html About.html my page.html
확인 지점내 사이트 안의 다른 페이지로 갈 때 상대 경로를 쓰는 이유를 한 문장으로 설명할 수 있으면 통과.
1

웹 스튜디오에 내 페이지 불러오기

지금 볼 탭 · GitHub ↔ 웹 스튜디오

4차시까지 만든 my-page의 index.html 코드를 웹 스튜디오로 가져와요. 4차시에 붙인 OX 투표·방명록도 그대로 따라와요.

웹 스튜디오 열기 ↗
코드는 누가 고칠까?웹 스튜디오에서 무언가를 바꾸면 그때마다 HTML 코드가 자동으로 고쳐져요. 오른쪽 코드 탭을 누르면 방금 바뀐 줄이 초록색으로 보여요.
확인 지점웹 스튜디오 미리보기에 내 페이지가 보이고, 글자 하나를 고쳤을 때 미리보기가 바뀌면 통과.
2

새 페이지 2개 만들고 채우기

지금 볼 탭 · 웹 스튜디오

나를 더 소개할 페이지 2개를 만들어요. 예: about(소개) · favorite(좋아하는 것) · gallery(사진) · dream(진로). 새 페이지는 저장소에 새 파일로 올라가요.

요소를 고르기 어려우면오른쪽 위 경로(body › main › …)에서 바깥 요소를 누르거나, 안쪽 요소 고르기 버튼을 써요. Esc를 누르면 한 단계 바깥 요소가 선택돼요. 실수하면 위쪽 ↶ 되돌리기(Ctrl+Z).
확인 지점왼쪽 페이지 목록에 index.html과 새 파일 2개(초록색 새 파일)가 보이고, 새 페이지마다 내 내용이 들어 있으면 통과.
3

메뉴와 버튼으로 페이지 연결하기

지금 볼 탭 · 웹 스튜디오

페이지가 있어도 링크가 없으면 방문자는 찾아갈 수 없어요. 모든 페이지 맨 위에 같은 메뉴(내비게이션)를 넣고, 첫 페이지에는 다른 페이지로 가는 버튼도 넣어요.

확인 지점동작 보기에서 메뉴로 세 페이지를 모두 오가고, index.html의 버튼으로 다른 페이지에 갈 수 있으면 통과.
4

점검하고 GitHub에 올리기

지금 볼 탭 · 웹 스튜디오 ↔ GitHub

웹 스튜디오의 올리기 탭이 파일마다 무엇을 해야 하는지 알려 줘요. 이미 있는 파일(수정됨)은 연필로 고치고, 새 파일(새 파일)은 새로 만들어요.

확인 지점GitHub 저장소 첫 화면에 HTML 파일 3개가 보이고, 웹 스튜디오 페이지 목록이 모두 회색 올림이면 통과.

안 될 때

"React 코드예요"라고 나와요 / 미리보기가 흰 화면이에요

GitHub에 올라간 코드가 웹페이지가 아니라 React 코드예요. Gemini에게 "React 없이 HTML 파일 하나로 다시 만들어 줘"라고 요청해 받은 코드를 붙여넣어요.

"HTML 코드가 아니에요" / "GitHub 화면 전체를 복사했어요"라고 나와요

연필 ✏ 화면에서 코드 칸 안을 한 번 누른 뒤 Ctrl+A → Ctrl+C 해요.

원하는 부분이 안 눌려요 / 너무 큰 상자가 선택돼요
  • 오른쪽 안쪽 요소 고르기 버튼으로 한 단계씩 들어가요.
  • "JS가 실행 중에 만든 부분"이라고 나오면 그 부분은 코드에 없어서 고칠 수 없어요. 바깥 요소를 옮기거나 지우는 것만 돼요.
블록이 엉뚱한 곳에 들어갔어요

블록을 고르면 미리보기에 ⠿ 끌어서 옮기기 손잡이가 생겨요. 손잡이를 잡고 끌면 분홍 줄이 놓일 자리를 보여 주고, 놓으면 그 자리로 옮겨져요. 오른쪽 ▲ 위로 / ▼ 아래로로 한 칸씩 옮겨도 돼요. 더 이상 안 움직이면 바깥 요소 고르기를 눌러 바깥 상자째 옮겨요. 아니면 ↶ 되돌리기 후 넣을 자리 위의 요소를 먼저 누르고 다시 넣어요.

"이 페이지 이름은 쓸 수 없어요"라고 나와요

파일 이름은 영어 소문자·숫자·하이픈(-)만 돼요. 한글·대문자·띄어쓰기를 빼요. index는 첫 페이지 이름이라 쓸 수 없어요.

배포 확인에서 ✗ 404가 나와요 / 내 사이트에서 새 페이지가 404예요
  • 1~2분 기다린 뒤 Ctrl+F5.
  • GitHub 저장소에 그 파일이 있는지, 이름이 웹 스튜디오와 똑같은지(.html 포함, 소문자) 확인해요.
  • 파일 이름 끝이 about.html.html이나 about(확장자 없음)이 아닌지 봐요. 파일을 누르고 연필 ✏ 화면에서 이름을 고칠 수 있어요.
어떤 페이지에는 메뉴가 있고 어떤 페이지에는 없어요 / 메뉴 항목이 달라요

메뉴는 파일마다 들어 있어서, 바뀐 파일을 모두 올려야 똑같아져요. 웹 스튜디오 올리기 탭에서 수정됨인 파일을 모두 다시 올려요.

OX 투표·방명록이 사라졌어요

웹 스튜디오에서 실수로 지웠을 수 있어요. ↶ 되돌리기를 누르거나, 이미 올렸다면 GitHub의 index.html → History에서 이전 코드를 확인해요. 미리보기에서는 예시 데이터만 보이고 실제 저장은 되지 않는 게 정상이에요.

다른 컴퓨터에서 하니 웹 스튜디오가 비어 있어요

웹 스튜디오는 그 컴퓨터의 브라우저에만 저장돼요. 내려받아 둔 파일이 있으면 내려받아 둔 파일 불러오기로 모두 고르고, 없으면 GitHub에서 index.html을 붙여넣어 시작한 뒤 나머지 페이지는 새 페이지 → 코드 붙여넣기로 하나씩 가져와요.

사진을 넣었더니 코드가 너무 길어요

내 컴퓨터의 사진은 코드 안에 글자로 바뀌어 들어가서 길어져요. 사진은 페이지마다 2~3장 정도만 넣거나, 인터넷 이미지 주소를 써요.

오늘의 용어

정적 웹사이트서버가 저장된 파일을 그대로 보내 주는 웹사이트. GitHub Pages가 대표적이에요.
index.html폴더 주소로 들어왔을 때 가장 먼저 열리는 기본 페이지
URL웹 자원의 위치를 나타내는 주소. https://아이디.github.io/my-page/about.html
하이퍼링크다른 페이지로 이동하게 해 주는 연결. HTML에서는 <a href="…">
상대 경로 · 절대 경로지금 위치를 기준으로 찾는 주소(about.html)와 처음부터 다 적은 주소(https://…)
내비게이션사이트 안의 페이지로 이동하는 메뉴. 모든 페이지에 같은 모양으로 두어야 사용자가 헷갈리지 않아요(일관성).

5차시 정리

오늘 만든 것: 파일 3개로 이루어진 정적 웹사이트. 파일 이름이 주소가 되고, 링크(<a href>)와 상대 경로로 페이지끼리 연결돼요. 다음 시간에는 이 사이트를 사용하기 편한 화면으로 다듬어요.
